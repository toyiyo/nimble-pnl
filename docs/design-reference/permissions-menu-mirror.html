What it takes to build

Three of these are UI. One is a migration, and it's the one that buys the control you're missing.

DB One area per page

area_catalog grows from 14 keys to one per gateable page, and its ui_group/sort_order columns are re-seeded from navigationGroups instead of the three bands.

Existing roles migrate mechanically: a role holding books: view gets view on all nine pages that books covered — nobody gains or loses access on deploy day.

UI The menu is the schema

AREA_DEFINITIONS stops being a hand-kept list and is derived from navigationGroups, so a new page added to the sidebar shows up in the editor automatically instead of silently becoming ungrantable.

That's what closes the five-page hole — and stops it reopening.

UI Roll-up, then refine

33 rows is a wall, so groups collapse to a single control and a 4/6 summary. Hitting Manage on a group header sets every page under it; touching one page turns the header MIXED.

Granting a whole area stays one click — you just get to go deeper when you need to.

Guard Caps survive the re-cut

Per-page caps replace per-area ones: read-only surfaces lock Manage, and /team stays ungrantable to any collaborator role — the privilege-escalation guard role_areas_enforce_collaborator_cap already enforces in SQL.

Pages that genuinely move money (/print-checks) keep their own note on the row.
