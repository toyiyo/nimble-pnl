::finding:: severity=major file=supabase/migrations/20260731000000_tip_role_percentages.sql line=32
The `role_percentages` CHECK enforces only presence and numeric range comparisons, but never enforces that `percentage` is actually a JSON number. A client with write access can store `{"Manager":{"mode":"at_least","percentage":"abc"}}`: the key exists, and the jsonpath `< 0 || > 100` predicate does not reject a non-numeric string. When that setting is read back, `calculateTipSplitWithGuarantees` computes `Math.round(totalTipsCents * (rule.percentage / 100))`, producing `NaN`, which can make live splits/review amounts display or persist invalid values instead of cents.
