::finding:: severity=major file=src/hooks/useShifts.tsx line=203
`createRecurringShifts` preserves the parent shift's elapsed `durationMs` for every child, but recurring shifts are wall-clock schedules. For an overnight recurrence across DST, this creates the wrong end time: e.g. in `America/Chicago`, a parent `2026-03-07 22:00 -> 2026-03-08 06:00` is a 7-hour instant duration because spring-forward removes an hour; the next daily child starts correctly at `2026-03-08 22:00`, then line 203 adds 7 hours and stores `05:00` local instead of the intended `06:00`. The fix needs to carry the restaurant-local end wall clock/date rollover too, not only `durationMs`.
