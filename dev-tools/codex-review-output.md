::finding:: severity=major file=src/hooks/useRecipes.tsx line=540
The realtime echo guard is armed only after the heal `upsert` resolves, because `recordHealEchoes` runs in `.then(...)`. A cost-heal UPDATE can be delivered over Supabase realtime as soon as the DB transaction commits, and that websocket event can reach `subscribeToRecipeChanges` before the HTTP upsert promise settles. In that race, `isHealEcho(changedId)` returns false, the hook invalidates `['recipes', restaurantId]`, refetches, and can re-enter the heal/write/realtime loop this change is supposed to suppress. The ids need to be recorded before issuing the write, then cleared/expired if the write fails.
